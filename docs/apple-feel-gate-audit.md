order to make it pass; strengthening only with a negative control and
disclosure by line.** Every script under `scripts/` that differs from master on
this branch is listed (`git diff --stat b633f44..HEAD -- scripts/`: eleven

- **STRENGTHENED** -- every assertion master had still holds, and more are added.

  label or module path, or a harness change that alters no assertion.

  found**, so nothing is restored by this audit.

## Method

- Every diff read in full (`git diff b633f44..HEAD -- scripts/<gate>.mjs`); the
  eleven files are the complete set `git diff --stat` names.
- For `check-design-system` the two widened ratchets were tested against
  their old regexes file by file (a Node script over the pinned lists): none
  of the 15 focus pins matches `focus:outline-none`; of the 17 glyph pins,
  only the four that were already pinned on master match the old emoji-only
  regex.
- For `check-i18n-time-projects-people` the negative control above was run
  and the file restored byte-for-byte before committing (`git status` clean).
- For `check-my-work-survives-nulls` the deleted file's dead status was checked
  on master with `git grep`.
- The one gate change made in the pass this audit belongs to
  (`PageTitle.tsx` into `SCALE_OWNED`, 86c247a) is a strengthening and carries
  its own negative control in that commit's message.

No verdict is WEAKENED; no restore commit is needed. If a reader disagrees
with the `"next"` allow-list row, the alternative is to give the pager and the
adjective different English strings, which is product copy, not a gate.
